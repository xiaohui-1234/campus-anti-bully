# 部署说明

## 环境依赖

- JDK 17+
- Maven 3.9+
- MySQL 8
- Redis
- MinIO
- EMQX 或兼容 MQTT Broker
- SMTP 邮件服务，用于邮箱验证码
- Node.js 20+
- 微信开发者工具
- STM32/Keil 环境用于主控固件编译烧录

## 数据库初始化

新环境直接执行：

```bash
mysql -uroot -p < sql/campus.sql
```

脚本会创建 `campus` 数据库和核心表。根目录脚本包含开发种子设备和管理员，生产环境请替换或删除。

已有旧库升级账号安全能力时执行：

```bash
mysql -uroot -p campus < sql/upgrade_account_security.sql
```

升级后确认 `user` 表已包含 `security_email_hash`、`security_email_cipher`、`password_hash`、`token_version` 等字段。

如果账号安全字段已经升级过，只需要补齐开发管理员的新后台登录方式，可执行：

```bash
mysql -uroot -p campus < sql/init_admin_password_login.sql
```

## 后端部署

```bash
cd campus-server
mvn clean package
java -jar target/campus-server-1.0.0.jar
```

生产环境必须外部覆盖以下敏感配置：

- `spring.datasource.url`
- `spring.datasource.username`
- `spring.datasource.password`
- `spring.data.redis.host`
- `spring.data.redis.password`
- `spring.mail.host`
- `spring.mail.port`
- `spring.mail.username`
- `spring.mail.password`
- `campus.security.jwt.secret`
- `campus.security.crypto.hmac-secret`
- `campus.security.crypto.aes-key`
- `campus.wx.miniapp.app-id`
- `campus.wx.miniapp.app-secret`
- `campus.minio.endpoint`
- `campus.minio.access-key`
- `campus.minio.secret-key`
- `campus.mqtt.broker-url`
- `campus.mqtt.username`
- `campus.mqtt.password`

不要把真实密钥提交到仓库。生产环境不要在日志中打印 JWT、openid、设备密钥、MinIO secret 或邮箱验证码明文。开发阶段可使用 mock 验证码，生产环境应关闭 mock 并配置真实 SMTP。

## 账号安全配置

账号相关配置位于 `campus.security`：

```yaml
campus:
  security:
    jwt:
      access-token-expire-seconds: 1800
      refresh-token-expire-seconds: 604800
    password:
      min-length: 8
      max-length: 64
      bcrypt-strength: 10
    email-code:
      code-length: 6
      ttl-seconds: 300
      resend-interval-seconds: 60
      max-attempts: 5
      max-ip-sends: 20
      mock: false
      from: ${CAMPUS_MAIL_FROM:no-reply@example.com}
    security-email-change:
      grant-ttl-seconds: 600
      ticket-bytes: 32
    login-limit:
      enabled: true
      max-fail-count: 5
      lock-seconds: 900
    crypto:
      hmac-secret: ${CAMPUS_HMAC_SECRET:change-me}
      aes-key: ${CAMPUS_AES_KEY:change-me}
```

说明：

- `access-token-expire-seconds` 建议保持较短，当前为 30 分钟。
- 修改密码或重置密码后会递增 `token_version`，旧 refresh token 失效。
- 修改安全邮箱不会强制下线。
- `hmac-secret` 用于安全邮箱哈希、验证码哈希、限流 key 哈希等。
- `aes-key` 用于加密安全邮箱明文，必须长期稳定保存；更换后旧安全邮箱无法解密。

## 后台部署

```bash
cd campus-admin-web
npm install
npm run build
```

构建产物在 `dist`。部署时需要让 `/api/v1`、`/backend/v1`、`/ws/v1/client` 反向代理到后端服务。

当前配置后台是管理端，登录走 `/api/v1/auth/password/login`，只允许 `ADMIN` 角色进入。开发种子管理员可使用 `admin@example.com` 或 `usr_admin` 加 `Admin123456` 登录；生产环境必须替换或删除该种子管理员。

若要做普通用户 Web 端，建议新增独立用户端页面，复用 `/api/v1/auth/password/*`、`/api/v1/auth/email-code/send`、`/api/v1/users/me` 和现有设备/事件接口。

Web 正式上线时建议：

- CORS 限定为实际域名，不使用开放通配。
- HTTPS 强制启用。
- 根据部署方式选择 token 存储策略。开发阶段可用 `localStorage`，正式环境建议评估 `HttpOnly Cookie` 或更严格的前端安全策略。

## Android/Web 移植

后端账号系统已经支持 Android/Web 复用，不需要依赖微信 openid：

- 注册：`POST /api/v1/auth/password/register`
- 登录：`POST /api/v1/auth/password/login`
- 找回密码：`POST /api/v1/auth/password/reset`
- 发送验证码：`POST /api/v1/auth/email-code/send`
- 当前用户：`GET /api/v1/users/me`
- 密保管理：安全邮箱修改和密码修改接口

客户端需要自行实现：

- Bearer token 请求拦截器。
- 401 后使用 refresh token 刷新 access token。
- token 安全存储和退出登录。
- 邮箱验证码倒计时和错误提示。
- 密保管理页面状态机。

## 小程序部署

1. 使用微信开发者工具打开 `campus-miniprogram`。
2. 修改 `config/env.js`：

```js
baseUrl: 'https://your-domain.example/api/v1'
wsUrl: 'wss://your-domain.example/ws/v1/client'
```

3. 配置微信小程序合法域名：
   - request 合法域名：后端 HTTPS 域名。
   - socket 合法域名：WebSocket WSS 域名。
   - upload/download 合法域名：后端和对象存储公网域名。

小程序当前支持微信登录，并在个人页进入密保管理。没有安全邮箱和密码的微信账号，可先设置安全邮箱和登录密码，之后即可在 Android/Web 使用邮箱或 `user_id` 加密码登录。

## EMQX/MQTT

后端通过 `campus.mqtt.*` 连接 Broker。设备侧使用 ESP8266 AT 指令连接同一 Broker。topic 必须保持：

```text
device/{product_type}/{device_id}/{action}
```

硬件联调前确认：

- Broker TCP 端口对设备可达。
- 后端能连接 Broker。
- 设备 MQTT 用户名/密码与 Broker 认证配置一致。
- 后端 `campus.mqtt.enabled=true`。
- EMQX 客户端列表中出现 `campus-server` 表示后端 MQTT 客户端已连接，这是正常现象。
- 同一 `campus.mqtt.client-id` 同一时间只能被一个后端实例使用。多个实例都使用同一 client-id 时会互相顶掉连接，后端日志会反复出现 `MQTT connection lost`、`MqttException: 已断开连接`、`EOFException`。

当前后端 MQTT 消费使用普通通配订阅，没有使用 shared subscription。生产或测试环境建议只启动一个 `campus.mqtt.enabled=true` 的后端实例；如需多开后端实例做 HTTP/WebSocket 联调，其他实例应关闭 MQTT，或临时使用不会与主实例冲突的 `client-id` 并避免同时消费设备上报 topic。

## MinIO

后端需要能访问 MinIO `endpoint`，设备需要能访问预签名上传 URL 对应的公网地址。若设备只能访问 HTTP，应确保 `upload_url` 的协议、host、端口对 ESP8266 可达。

## STM32 主控

1. 修改 `stm32主控源码/联网测试win/Hardware/campus_config.h` 中 WiFi、EMQX、设备 ID、产品类型、设备 MQTT 认证等配置。
2. 使用 Keil 打开 `Project.uvprojx` 编译烧录。
3. 确认 TF 卡、麦克风/录音、ESP8266、按键和供电稳定。
4. 设备启动后应连接 WiFi、连接 MQTT、订阅 `alarm/upload`、周期上报 `status/online`。
